# Kimi Code Adaptation Guide (ARIS Workflows)

> Use ARIS research workflows in **Kimi Code CLI** — Moonshot AI's terminal agent.

Kimi Code natively discovers `SKILL.md` skills (YAML frontmatter + Markdown body). ARIS ships a **Kimi-native package** `skills/skills-kimi/` (generated by `tools/build_skills_kimi.py` from `skills/skills-codex/`, with the portable business set copied byte-for-byte from canonical `skills/`). The Kimi and Codex packages have **diverged** — different reviewer-backend contracts — while `.agents/skills/` is a discovery path shared by both CLIs, so **one project runs exactly one release line**.

## 1. Where Kimi Code Looks for Skills

| Scope | Path | Notes |
|-------|------|-------|
| Project | `<project>/.agents/skills/<name>/SKILL.md` | This is also the Codex CLI discovery path — shared by design |
| User (Kimi) | `~/.kimi-code/skills/<name>/SKILL.md` | Available across all projects |
| User (shared) | `~/.agents/skills/<name>/SKILL.md` | Cross-host user scope |

Project instructions live in `AGENTS.md` (same convention as Codex CLI).

## 2. Install

```bash
git clone https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep.git
cd Auto-claude-code-research-in-sleep

# Project-local install (recommended): symlinks into <project>/.agents/skills/
bash tools/install_aris_kimi.sh ~/your-project --office-author "Your Name"

# User-level install: symlinks into ~/.kimi-code/skills/
bash tools/install_aris_kimi.sh --global

# Update later (when upstream changes)
git pull
bash tools/install_aris_kimi.sh ~/your-project --reconcile --office-author "Your Name"
# (NEW upstream skills need confirmation — --add-new to accept all non-interactively)

# Or one command: fetch + checkout newest -kimi-* tag + reconcile each install
bash tools/smart_update_kimi.sh --apply --project ~/your-project   # dry-run without --apply

# Uninstall (removes only manifest-managed entries, never your own skills)
bash tools/install_aris_kimi.sh ~/your-project --uninstall
```

Selection flags match the other ARIS installers: `--list-groups` / `--groups A,B` / `--skills X,Y` / `--exclude X,Y` / `--all`, driven by the shared catalog `tools/skill-groups.tsv`.

### What gets installed

- **Source package:** `skills/skills-kimi/` only. The Codex packages (`skills-codex`, `skills-codex-claude-review`, `skills-codex-gemini-review`) and the `skills-kimi` package directory name itself are never scanned as installable skills.
- **Layout:** one symlink per skill at `.agents/skills/<name>` (project) or `~/.kimi-code/skills/<name>` (global).
- **Manifest:** `.aris/installed-skills-kimi.txt` (project) or `~/.aris/installed-skills-kimi.txt` (global). Uninstall/reconcile only ever touch manifest-managed entries.
- **AGENTS.md:** project installs maintain a managed block `<!-- ARIS-KIMI:BEGIN/END -->`; `--global` installs skip it (no project file).

### One release line per project (Codex coexistence)

If `install_aris_codex.sh` already manages a selected name in the same project (listed in `.aris/installed-skills-codex.txt`), the Kimi installer **hard-fails with a CONFLICT** and writes nothing — the two packages diverged and share the `.agents/skills/` discovery path, so they cannot co-manage one project. Codex-managed names your Kimi selection does not need are left untouched, and Kimi uninstall/reconcile never touch Codex-owned entries.

To switch a project from the Codex line to the Kimi line:

```bash
bash tools/install_aris_codex.sh ~/your-project --uninstall
bash tools/install_aris_kimi.sh  ~/your-project --office-author "Your Name"
```

### Release convention

One unified release covers both hosts. Tag naming: `<suite>-vX.Y.Z` (e.g. `business-research-suite-v0.5.0`); the release notes give both install commands — `tools/install_aris_kimi.sh` for Kimi Code, `tools/install_aris_codex.sh` for Codex — and a project picks exactly one line. Upgrade a Kimi-line project with `bash tools/smart_update_kimi.sh --apply --project <path>` (or `git checkout <tag>` + `install_aris_kimi.sh --reconcile`). Legacy `<suite>-kimi-vX.Y.Z` tags still match `smart_update_kimi.sh`'s default lookup, but no new split tags will be cut.

## 3. Data & Browser Channels Under Kimi Code

### kimi-datasource (public API layer)

`business-research-pipeline` already registers the `kimi-datasource` plugin as the preferred bounded public API layer under Kimi Code (`mcp__plugin-kimi-datasource_data__get_data_source_desc` → `...__call_data_source_tool`): `wind` / `stock_finance_data` for A-share/HK quotes and financials, `sp_data` / `sec_edgar` / `yahoo_finance` for US fundamentals and filings, `china_nbs` / `fred` / `imf` / `world_bank_open_data` for macro, `tianyancha` for corporate registry, `china_standards` / `yuandian_law` for standards and law, `arxiv` / `scholar` for literature metadata, `xhcj` / `caixin` for financial news. It does **not** cover WRDS, CSMAR/CNRDS research tables, CNKI, or publisher fulltext.

### Browser channel: kimi-webbridge

`browser-session-bridge` is host-adaptive: under Kimi Code it binds the `kimi-webbridge` local daemon (driving the user's real browser) as the trusted backend (`client_runtime: kimi`, `adapter: kimi_webbridge`), replacing Codex's native Chrome plugin. CNKI / SSRN / ScienceDirect / CSMAR / CNRDS authenticated navigation and verified downloads follow the same contract; `kimi_webbridge` has no download event, so the contract's narrow new-and-stabilized-file fallback applies.

### Unchanged routes

- **WRDS:** still via `wrds-query-bridge` (R + Postgres) or the `wrds-sas-cloud` handoff.
- **CNRDS / CSMAR:** still via `cn-data-bridge` portal exports.
- **CNKI / publisher fulltext:** still via `fulltext-acquire` + `browser-session-bridge` (now on the `kimi_webbridge` adapter).

## 4. Reviewer Backends (important)

Review-heavy skills (`auto-review-loop`, `paper-claim-audit`, `citation-audit`, `proof-checker`, …) in `skills-kimi` use the **Kimi-native subagent reviewer contract** out of the box — `kimi_subagent` for round 1, `kimi_subagent_continue` (with `resume:`) for follow-ups, no extra setup. Because the reviewer subagent is the same model family as the executor, every base review records `review_independence: same-family` / `acceptance_status: provisional` — honest, but not cross-family.

The **cross-family upgrade path** (verdicts that can record `accepted`):

1. **Any OpenAI-compatible API via `llm-chat`** (DeepSeek, GLM, MiniMax, GPT, …) — see the MCP registry in [`SETUP_GUIDE.md` §3.2](../SETUP_GUIDE.md) and [`docs/LLM_API_MIX_MATCH_GUIDE.md`](LLM_API_MIX_MATCH_GUIDE.md):
   ```bash
   python3 -m venv .venv
   .venv/bin/pip install -r mcp-servers/llm-chat/requirements.txt
   # then register mcp-servers/llm-chat/server.py as an MCP server in Kimi Code
   ```
2. **Zero-cost manual review** via `mcp-servers/manual-review` (`— reviewer: manual`).
3. Codex MCP remains an option if you also have Codex installed (`codex mcp-server`).

Without a cross-family channel, review loops still run end-to-end, but submission-facing reports expose `submission-ready: provisional` rather than `yes`.

## 5. Quick Reference

```bash
# Install / update / uninstall
bash tools/install_aris_kimi.sh ~/your-project --office-author "Your Name"
bash tools/install_aris_kimi.sh ~/your-project --reconcile --add-new
bash tools/install_aris_kimi.sh ~/your-project --uninstall

# Global (user-level)
bash tools/install_aris_kimi.sh --global
bash tools/install_aris_kimi.sh --global --uninstall
```

In Kimi Code, invoke skills by name in natural language (the agent auto-discovers them from each skill's `description`), e.g. "run the business-research-pipeline for <topic>".

## 6. Migration Checklist

- [ ] `bash tools/install_aris_kimi.sh <project>` (or `--global`)
- [ ] Verify `.aris/installed-skills-kimi.txt` and the `ARIS-KIMI` block in `AGENTS.md`
- [ ] If the project previously used the Codex line: `install_aris_codex.sh <project> --uninstall` first — the installer refuses codex-managed names (CONFLICT)
- [ ] Base reviews run natively (`kimi_subagent`, same-family / provisional); register `llm-chat` (or equivalent) when you need a cross-family accepted route
- [ ] For business workflows: prefer `kimi-datasource` for covered public data; keep WRDS/CNRDS/CSMAR/CNKI on their existing routes
